pi Plan Mode UI 重构 — 三方案

现状：ExtensionDialogCard.vue 一张卡应付 select / confirm / input / editor 四种引擎对话框，标题是一段多行纯文本、选项是无层级按钮，且与 plan_mode_question / plan_mode_complete 的工具调用卡片互不关联。以下三个原型回答同一件事：pi 专属工具的 UI 应该长成什么样。

演示故事（三个原型共用）：「给设置页加主题预览」→ pi 提出问卷（plan_mode_question，2 题）→ 提交计划（plan_mode_complete）→ 用户批准实施。每页均含深浅主题、汇总/超时等边界态，可直接交互。
A

卡片同构

轴线：对话流内联卡片为中心

pi 工具卡并入现有卡片家族 —— plan_mode_question 完全对齐 AskUserQuestionToolCard（图标头 / 进度点 / 选项描述 / 自定义输入 / 汇总折叠），plan_mode_complete 升级为带目录与行动条的计划文档卡。

胜在：与你的参考方向一致；学习成本零；改动收敛在 tool cards 层
代价：问答与计划仍是时间线里的两张卡，跨卡上下文要靠滚动
B

计划文档中心

轴线：决策文档 + 行动条为中心

plan_mode_complete 升格为「决策文档」主角：标题栏 + 工具栏 + 分节正文 + 步骤文件落点 + 底部行动条（批准 / 再改改 / 存草稿 / 放弃）。问卷收成一行 chip，点开浮层作答。

胜在：决策动作集中一处；计划阅读体验最好；贴合 plan mode 的本质
代价：问卷被压缩，多题时浮层答题略局促；实现面更大（文档卡 + 浮层）
C

会话面板中心

轴线：会话级状态中枢为中心

新增右侧常驻 Plan 面板：当前问题答题器、计划摘要与行动、带实时时钟的活动时间线都收进面板；聊天流只留可点击的轻量 chip 提醒。

胜在：plan 全程状态一屏可见；聊天不被大卡打断；chip 模式对长会话最友好
代价：新增面板层，需与 splitLayout / InfoPanel 抢宽度，窄窗口要降级；改动面最大
选择建议：想最小风险拿到「与 AskUserQuestion 同一家族」的观感 → A；想让 plan mode 的核心产出（计划）获得最好的阅读与决策体验 → B；想要一个 plan 专属的常驻驾驶舱并接受面板布局成本 → C。三个方案共享同一套语义 token 映射与数据降级策略，选定后可在细化阶段互相吸收细节（如 A 吸收 B 的目录、C 吸收 A 的选项卡）。
