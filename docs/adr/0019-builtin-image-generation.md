# 内置生图：免安装技能 + 主进程回环 MCP + 三方言客户端 + 宿主授权闸门

## Status

Accepted（2026-11-15）。术语见根目录 `CONTEXT.md` 的 Image Generation 与 Agent Registry 两节。产品口径见 `docs/prd/imagegen.md`。

## Context

生图与生成式 UI（ADR 0016）看起来相邻，实际不同类：卡片生成只需要**按需加载的说明**，不需要运行时工具；生图必须真的发出计费的网络请求、拿到字节、落盘。说明可以只靠技能，能力不行。

三条既有路都不可用：

- **让模型自己装 SDK 跑脚本**：API key 进会话、网络出口交给临时生成的代码、每个会话重来一遍。
- **做成引擎扩展**：只有认得那套扩展的引擎能用。本项目的两个引擎里只有一个有扩展机制，另一个的用户什么也看不到。
- **挂在引擎的权限管线上做计费闸门**：`can_use_tool` / control_request 那套协议在引擎契约里是可选的，**目前只有 Claude Code 实现**；Pi 走的是扩展对话框。挂上去等于只保护一半用户。

同时，「OpenAI 兼容」在图像接口上是个不成立的说法。实测三家供应商在改图端点、批量能力、返回形态、错误位置上互不相同，其中一家把逐图错误藏在 HTTP 200 里，另一家根本没有改图端点。

权限与取消这两件事在本项目里各有一条现成的、但容易被挂错的链路：

- 权限卡表按**工具调用 id** 索引，是 Claude 权限链路的承重墙；而 MCP 调用帧**不携带工具调用 id**（引擎的可选 meta 参数在调用点未被填充），宿主无法把一次 MCP 调用挂到那张表上。
- 宿主问答表按**对话框 id** 索引，时间线上不需要对应工具条目，本来就带 id 应答、看门狗、进程丢失清理与时间线锚点。

## Decision

1. **三条链路解耦**：发现（纯说明的内置技能）、执行（主进程回环 MCP）、配置（设置分区 → 全局配置文件）。任一条可独立验证。
2. **技能沿用 ADR 0016 的单份正文双 Target**：一份内置技能种入中心库、标记 bundled，同时装到两个引擎的技能目录。**不写引擎扩展、不维护第二份提示、技能正文不含任何凭证。**
3. **执行面是主进程回环 HTTP MCP**，外壳从既有内置 MCP 服务器抽出为可参数化通用件，两者共用：随机端口、Streamable HTTP、无状态、每轮 Bearer token（定长比较）、Host 白名单、请求体上限、不发 CORS 头。stdio 被否决（见 Alternatives）。
4. **三种方言，不是一个协议**：`openai`（JSON 生成 / multipart 改图 / 原生张数 / base64 或短期 url）、`seedream`（生成与改图同一端点、参考图走 data URL 数组、顺序生成不保证张数、**逐图错误在 HTTP 200 内**）、`zhipu`（只有生成、**无改图端点**、**无批量**、仅 url）。方言差异由客户端吸收，工具契约对模型稳定。
5. **张数一律客户端扇出，每次物理请求只要一张**，并发上限 2，扇出与批量共享。不用供应商原生批量参数：一家不保证张数、一家没有批量；扇出还让每张图有独立的成功/失败/取消归属。
6. **配置全局、与 Profile 无关**，类型与预设表放 main/renderer 共享层（放主进程模块会把 fs/os 拖进浏览器 bundle）。预设填 base URL 与默认模型，**模型名始终可编辑**。去水印默认关闭——智谱要求先签声明。
7. **未配 key 时工具照常暴露**，返回工具错误并指向设置。「不注入」被否决：那样失败是不可见的，模型只会说自己没有生图能力。
8. **每次调用在第一个出站请求之前必须取得宿主授权**，闸门由宿主自持、与引擎无关。**复用既有的宿主问答通道**（select 形态、宿主自铸对话框 id），不新建卡片、不新建 IPC 通道。统一网关在把应答交给引擎之前先查宿主授权登记表，命中就地兑现——这是本特性唯一新增的判定点。
9. **授权模式读用户选定的每会话模式**（ADR 0012 口径，同 `shouldAutoApprovePermission`）：完全信任自动放行并留痕，其余问。「本会话总是允许」只作用于该会话，不写全局、不跨重启。无人应答按既有宿主看门狗时长**拒绝**（fail closed），绝不挂死。
10. **取消入口收敛在统一网关**：中止 / 停止 / 挂起三个动作先取消该会话的在途生图工作，再走引擎原有语义；三个适配器的派发都委托到网关，一处覆盖全部端。会话进程退出与服务器停止同样触发。
11. **取消语义**：中止在途 HTTP、丢弃未开始的排队项、**已落盘文件保留**、逐图状态 `cancelled` 与 `failed` 分开。**取消 / 超时 / 失败一律不自动重试**——供应商可能已计费。技能必须写明中止本地请求不能保证供应商停止计费。
12. **鉴权失败快速止血**：401/403 立即取消剩余排队项，与用户取消共用中止机制、不同原因。
13. **供应商响应与其给出的 URL 一律按不受信输入处理**：响应体有界（先看 content-length 再在流上兜底）；base64 先量长度再解码，格式校验不用会爆栈的重复分组正则；图片按完整签名校验（PNG 魔数 + 首块标识、JPEG 起止标记、WebP 容器标识，**不收 GIF**），改图输入同样校验；输入路径**先 realpath 再判归属**；下载拒绝非 http(s)、URL 内嵌凭证、重定向，解析后钉定已校验地址，始终拒绝云元数据地址，且不携带供应商凭证头。
14. **multipart 单图与多图字段名不同**：一张用单数字段名，多张用数组字段名。恒用数组名会让部分端点拒收单图改图。
15. **产物落工作区生图输出目录**（已被产物服务扫描且不过滤扩展名，图片自动进面板），文件名 sanitize、冲突追加版本后缀、**绝不覆盖**。成功文本只带路径/尺寸/实际模型，**不带 base64**。
16. **卡片按完整 MCP 工具名注册**：工具组件表是精确名匹配、无前缀归一化。本地图片转 data URL 内联——渲染层 CSP 的 img-src 不含 `file:`。
17. **不改工具注册表**：那份表只喂设置里的工具开关列表与默认工具配置，MCP 工具按会话注入、不受其管辖；加三条只会造出三个点了没反应的开关。
18. **技能正文禁止两条实测坏行为**：不得把结果路径再以 Markdown 图片贴一遍（卡片已渲染，重复贴每张显示两次）；不得声称看过只拿到路径的图。
19. **漂移由测试钉住**：技能引用的工具名集合必须与工具定义完全一致；禁止字符串（外部 CLI 的目录变量、脚本名、他家模型名、抠色指令、环境变量式凭证）不得出现。

## Consequences

- 用户零安装获得能力，两个引擎口径一致；换引擎或新增 Agent 时只决定它的技能目录，不复制技能内容。
- 密钥只在主进程内存：不落 MCP 配置文件、不进引擎子进程环境、不回渲染层明文、不在错误与日志里回显。
- 计费出口有闸门：模型无法在用户看清供应商/模型/张数之前把请求发出去；无人值守会话靠完全信任模式放行，而不是靠「内置工具免检」。
- 授权对话框与 plan-mode 问卷共用一条通道，因此**标题与选项签名必须不相交**，否则会被那张卡抢走消费；这条由测试钉住。
- 引擎侧 MCP 工具默认超时极长（约 27.8 小时），授权卡不会被引擎提前判超时；宿主看门狗因此是必需的，不是优化项。
- 取消是尽力而为的本地语义：能停掉本地请求与排队，不能承诺供应商停止计费。文案与技能都必须如实说明，不得给出「已取消所以没花钱」的暗示。
- 三态逐图结果（成功/失败/取消）会传到卡片与技能两处；任何把 `cancelled` 折叠进 `failed` 的简化都会让用户分不清「我停的」和「它坏了」。
- 新增测试缝只有一条（参数化回环外壳工厂）；其余全部挂既有缝——真实 MCP SDK 客户端握手、注入 fetch 的方言客户端、工具分发面、技能服务 bootstrap、启动参数与 MCP 配置投影、Pinia store、组件 mount。
- 方言表是升级面：供应商改协议时只改客户端与方言表，工具契约与技能正文不动；反之若工具名变了，技能漂移测试会红。

## Alternatives considered

- **stdio MCP 服务器**：需要为每个会话拉起一个子进程并管理其生命周期，而回环 HTTP 外壳已经存在且已被鉴权/超限测试覆盖；已否决。
- **引擎扩展提供生图工具**：只有一个引擎有扩展机制，另一个的用户看不到能力；已否决。
- **把闸门挂引擎的 `can_use_tool` 管线**：该协议只有 Claude Code 实现，且 MCP 调用帧不带工具调用 id，宿主无法关联；已否决。
- **为授权新建一张卡片 + 一条 IPC 通道**：宿主问答通道已带 id 应答、看门狗、进程丢失清理与时间线锚点，新建等于把这些语义再实现一遍；已否决。
- **按工具调用 id 把授权挂到权限卡上**：需要宿主从引擎的工具流里反查并配对 id，MCP 帧本身不带它，配对在并发与重放下不可靠；已否决。
- **用供应商原生批量参数**：一家不保证张数、一家没有批量，且逐图归属会丢失；已否决。
- **把供应商 url 直接交渲染层加载**：绕过签名校验与下载约束，且把供应商地址暴露给渲染层；已否决。
- **未配 key 时不注入工具**：失败不可见，用户得不到可操作信息；已否决。
- **取消后自动重试未完成项**：供应商可能已计费，重试等于重复付费；已否决。
