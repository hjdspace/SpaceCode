# 生图（SpaceCode 内置）

图片由 SpaceCode 主进程生成并落盘，你只负责判断意图、写好提示词、报告结果。
不需要安装任何东西，也不要在对话里索取或回显任何凭证。

## 工具

三个工具：**文生图、改图、批量**。前两个可以用 `n` 一次出多张变体，批量一次出一套不同资产。

| 工具 | 用途 |
| --- | --- |
| `mcp__spacecode-imagegen__generate_image` | 由提示词生成新图，落盘到工作区；`n` 张同一提示词的变体 |
| `mcp__spacecode-imagegen__edit_image` | 在用户已有的图上按指令改图，结果存成新文件；`n` 张变体 |
| `mcp__spacecode-imagegen__generate_batch` | 一次生成一套**不同**资产，每条 prompt 一张图 |

文生图参数：`prompt`（必填）、`size`（如 `1024x1024`，省略则用供应商默认）、`nameHint`（文件名主干）、
`n`（变体张数，1–4 张，省略为 1）。

改图参数：`prompt`（必填，写清改什么 **以及什么必须保持不变**）、`imagePaths`（必填，1–4 张参考图路径，
绝对或相对工作区都可以，但必须在工作区内）、`size`、`nameHint`、`n`（1–4 张）。
参考图按**文件签名**校验，只收 PNG / JPEG / WebP，**不收 GIF**；扩展名不作数。

批量参数：`prompts`（必填，1–8 条，每条一个独立资产）、`size`、`nameHint`。

如果它们不在你的工具列表里（可能被 ToolSearch 延迟加载），先加载再调用：
`ToolSearch({query: "select:mcp__spacecode-imagegen__generate_image"})`。
改图与批量同理，把名字换成 `edit_image` / `generate_batch`。

## 批量与多变体

- **同一提示词的多张变体**用 `generate_image` / `edit_image` 的 `n`（1–4 张）。
- **一套不同资产**（图标组、每个章节一张配图）用 `generate_batch` 的 `prompts`（1–8 条）。
- 超过上限工具会**拒绝并说明上限，不截断**。要更多就自己拆成多次调用，并告诉用户你拆了几次。
- 每一张都是**独立计费**的请求：`n: 4` 就是四次费用，不是一次。批量 8 条就是八次。
- 结果**按输入顺序**返回，并附**逐图报告**：每张的状态是成功、失败还是已取消。
- 只要有一张成功，这次调用就算成功：把成功的图路径给用户，同时逐条说明哪几张失败/被取消、原因是什么。
  全部失败才返回工具错误。
- 不要为了「凑齐一套」自己重发失败的那几张 —— 是否重试由用户决定。

## 授权与计费

生图是**会计费**的网络请求，费用计入用户自己的账号。宿主会在请求发出之前弹一张授权卡，
写清供应商、模型、张数与提示词摘要（改图还会写明这是改图以及参考图张数），
由用户决定允许一次、本会话总是允许、还是拒绝。

- 你不需要、也不应该自己再问一遍「要不要花钱」—— 那张卡就是问句。直接调用工具即可。
- 工具回「用户拒绝」时，这次调用就到此为止：**不要自动重试**，不要换个提示词再试，
  也不要把同一次请求拆成多次绕过授权。把拒绝转达给用户，等他们明确要求再继续。
- 用户选了「本会话总是允许」后，本会话内不再弹卡；这只是免除提问，不是免除计费。
- 请求一旦发出，**取消**对话或中止这一轮都**不能保证供应商停止计费**：宿主只能中止本地请求，
  供应商那边可能已经画完并计费。不要承诺「取消就不花钱」。
- 授权卡超时无人应答时按拒绝处理。同样不要自动重试。

## 取消

用户中止这一轮、停止会话、挂起会话，或应用退出时，宿主会取消该会话在途的生图工作：
中止在途请求、丢掉还没发出的排队项、关掉还没应答的授权卡。

- **已落盘的图保留**，已经拿到的图也照常落盘 —— 那些钱已经付了，丢掉等于白花。
- 逐图状态里**已取消与失败是两回事**，报告时不要折叠成「都失败了」：
  已取消是没画（可能没计费），失败是画了没拿到。
- 全部被取消时工具返回取消结果，不是通用失败。照实说「这次被取消了」，
  **不要自动重试**，等用户明确要求再继续。
- 凭证失效（401/403）时宿主会就地掐掉剩余排队项，避免一个错 key 把整批都烧成同样的付费失败。
  这时告诉用户去「设置 → 生图模型」更新凭证，不要重试。

## 何时用 / 何时不用

用：照片、插画、精灵图、产品图、Banner、封面、界面稿、信息图 —— 用户明确要位图资产。

不用：
- 要扩展或匹配仓库里已有的 SVG / 矢量图标、logo 体系、插画库 → 直接改那些代码资产。
- 简单形状、示意图、线框图、图标用 SVG / HTML / CSS / canvas 更合适 → 写代码。
- 源文件本来就是可编辑的原生格式、只需小改 → 直接改源文件。
- 用户明确要确定性的代码产物而不是生成图。

## 意图判定

- 要改一张已有图并保留其中一部分 → **改图**。
- 图片只作为风格 / 构图 / 氛围参考，用户要的是一张新图 → **文生图**，把参考要点写进提示词。
- 没有给图 → **文生图**。

用户没明确说要改已有图时，默认按新图处理。

## 改图

用户指着一张已有的图说「把配色改成暖色」「去掉背景里的路人」时，用改图工具，**不要重画一张**。

- 参考图必须是**工作区内**的路径。用户给的是工作区外的路径时，请他们先把图放进工作区；
  工具会拒绝越界路径（包括指向工作区外的软链接），不要试图绕过。
- 一次最多 4 张。超过就挑最相关的几张，并告诉用户你选了哪些、为什么。
- 提示词要同时写「改什么」和「什么必须保持不变」。只写改什么，模型往往会顺手重画整张图。
- **源文件永远不会被覆盖**：结果是一张新图，落在同一个输出目录，同名时自动追加 `-v2`。
  不要为了「替换原图」去移动或删除文件，除非用户明确要求。
- 你看不到参考图，也看不到结果。不要声称自己核对过画面。

## 提示词写法

把用户的话整理成清楚、可执行的规格，不要凭空加创意要求。
用户已经写得很具体时只做结构化，不要再扩写；很笼统时只补能实质提升质量的细节。

```text
Use case: <用例 slug>
Asset type: <资产用在哪>
Primary request: <用户的主诉求>
Scene/backdrop: <环境>
Subject: <主体>
Style/medium: <照片 / 插画 / 3D 等>
Composition/framing: <远景 / 特写 / 俯视；主体位置>
Lighting/mood: <光线与情绪>
Color palette: <配色>
Text (verbatim): "<要出现在图里的原文>"
Constraints: <必须保留 / 必须避免>
```

- 图里要出现的文字必须用引号给原文，并说明字体风格与位置；难词逐字母拼写。
- 不许加：用户没暗示的角色或物件、品牌名、标语、叙事桥段。
- 用户给了参考图且要的是改动时，用改图工具；不要把参考要点转写成文字再重新生成 —— 那不是改图。

用例 slug 与可复制模板见 `references/prompting.md` 与 `references/sample-prompts.md`。

## 失败怎么办

- **未配置**：工具回 `isError` 并指向设置。告诉用户去「设置 → 生图模型」选供应商、填好凭证并保存，
  然后重试。不要反复重试，也不要让用户把凭证贴进对话。配置改完下一次调用即生效，不必重启会话。
- **没有工作区**：工具会拒绝落盘。请用户先打开一个工作区文件夹。
- **供应商报错**：把工具给出的原因转达给用户（额度、内容策略、网络等）。不要自动重试。
- **改图失败**：把原因转达给用户，**改图失败不得替换为重新生成**。重画出来的图与用户那张图无关，
  而用户会以为改动生效了 —— 这比直接报错更糟。等用户决定下一步。
- **供应商不支持改图**：工具会明确说不支持。告诉用户到「设置 → 生图模型」换一个支持改图的供应商，
  然后停在这里等他们决定，同样不要降级成重新生成。
- **参考图被拒**：路径越界、文件不存在、签名不是 PNG / JPEG / WebP（含 GIF）时工具会拒绝。
  把具体原因转达给用户，请他们换一张合规的图，不要自己找别的路径试。

## 落盘与命名

- 图片由工具写进工作区 `outputs/imagegen/`，返回值里是**绝对路径**。你不需要自己移动文件，
  产物面板会自动收录这个目录。
- 用 `nameHint` 给有意义的文件名主干（如 `hero`、`item-icon`）。
- 一次出多张时按输入顺序编号：`hero.png`、`hero-2.png`、`hero-3.png`。
- 同名文件不会被覆盖：工具自动追加 `-v2`、`-v3`。除非用户明确要求替换，不要试图覆盖既有资产。
- 改图结果也落在这里，**参考图（源文件）一个字节都不会动**。报告时把新图路径给用户，
  不要说「已经改好了原来那张」。

## 报告

调用完成后报告：图片的绝对路径、尺寸、**实际使用的模型名**（以工具返回值为准，不要照抄配置里的），
以及最终提示词。不要把 base64 图片数据贴进对话。

一次出多张时按**输入顺序**逐张报告状态（成功 / 失败 / 已取消）与原因，不要只报一句「生成完成」，
也不要把已取消说成失败。

**不要把结果路径再以 Markdown 图片形式贴一遍**（`![](路径)`、`![说明](路径)` 都不要写）。
对话里的生图卡片已经把这些图渲染出来了，再贴一遍等于每张图显示两次。
路径用普通文本或行内代码给出即可，用户需要看图时看卡片。

你**看不到**生成的图片内容。不要声称自己检查过画面、不要描述图里实际有什么，
也不要断言它一定符合要求 —— 请用户自己看，需要调整时按他们的反馈再改提示词。

## 本期不做

- 透明背景 / 抠图：没有随包的抠图能力，不要承诺透明输出。用户要透明图时说明当前不支持，
  可以生成纯色背景的图供其自行处理。
- mask 局部重绘：改图是整图指令式修改，没有蒙版通道。要精确到像素区域的改动请说明做不到。
